## What's New in 2.1.0

### 1. JWT Authentication

**Implementation**: `src/data/src/api/auth.rs`

- ✅ JWT token generation and validation
- ✅ Configurable via environment variables
- ✅ Optional auth middleware (can be disabled for development)
- ✅ Bearer token + X-API-Key support
- ✅ Auto-generated secrets via `run.sh`

**Environment Variables** (auto-generated by `run.sh start`):
```bash
DATA_SERVICE_JWT_SECRET=<32-char-random-secret>
DATA_SERVICE_JWT_EXPIRY=86400        # 24 hours
DATA_SERVICE_JWT_ENABLED=false       # true for production
```

**Usage**:
```bash
# Development (no auth)
DATA_SERVICE_JWT_ENABLED=false

# Production (auth required)
DATA_SERVICE_JWT_ENABLED=true

# Protected endpoints require:
curl -H "Authorization: Bearer <token>" \
  http://localhost:8080/api/v1/signals
```

**Protected Routes**:
- All `/api/v1/*` endpoints (signals, indicators, backtests)

**Public Routes** (no auth):
- `/health`
- `/metrics`
- `/ws/*` (WebSocket endpoints - can be protected later)

### 2. Discord Alert Integration

**Implementation**: 
- `scripts/monitoring/alertmanager-discord.py`
- `docker/Dockerfile.discord`
- `config/prometheus/alertmanager.yml` (updated)

**Features**:
- ✅ Rich Discord embeds with color-coded severity
- ✅ Alert grouping and deduplication
- ✅ Resolved alert notifications
- ✅ Runbook and dashboard links
- ✅ Error handling and retry logic

**Setup**:
```bash
# 1. Get Discord webhook URL
#    Discord Server > Settings > Integrations > Webhooks > New Webhook

# 2. Add to .env (run.sh generates template)
DISCORD_WEBHOOK_GENERALDISCORD_NOTIFICATIONS_ENABLED=true

# 3. Start services
./run.sh restart

# 4. Test alert
curl -X POST http://localhost:9093/api/v1/alerts \
  -H "Content-Type: application/json" \
  -d '[{
    "labels": {"alertname":"TestAlert","severity":"info"},
    "annotations": {"summary":"Test alert from staging"}
  }]'
```

**Alert Routing**:
- **Critical alerts** → Discord (red embeds, high priority)
- **Warning alerts** → Discord (orange embeds)
- **Info alerts** → Discord (blue embeds)
- **Resolved alerts** → Discord (green embeds)

**Alert Types**:
- Data completeness issues
- Exchange disconnections
- Indicator warmup failures
- Signal generation anomalies
- System resource alerts (CPU, memory, disk)

### 3. Testing Infrastructure

#### WebSocket Soak Test

**Script**: `scripts/testing/websocket-soak-test.py`

**Purpose**: Validate WebSocket stability over 48 hours

**Features**:
- Multiple concurrent connections (default: 10 clients)
- Automatic reconnection with exponential backoff
- Message rate tracking
- Connection stability metrics
- Periodic reporting (every 5 minutes)

**Usage**:
```bash
# Install dependencies
pip install websockets

# Run 48-hour test
python scripts/testing/websocket-soak-test.py \
  --url ws://localhost:8080/ws/signals \
  --duration 48 \
  --clients 10 \
  --report-interval 300
```

**Success Criteria**:
- Connection success rate: >95%
- Messages received: >10,000
- Avg message rate: >0.1 msg/sec per client
- Disconnections: <50 total
- Memory usage: Stable (not increasing)
- CPU usage: <20% average

## Deployment Workflows

### Staging Deployment (Quick Start)

**Estimated Time**: 30 minutes

```bash
# 1. Clone repo and navigate to project
cd /path/to/fks

# 2. Generate environment and start services
./run.sh start
# This will:
# - Generate .env with secrets
# - Build Docker images
# - Start all services

# 3. Configure Discord (optional)
nano .env
DISCORD_WEBHOOK_GENERAL./run.sh restart

# 4. Initialize QuestDB schema
curl -G http://localhost:9000/exec \
  --data-urlencode "query=$(cat config/questdb/init_signals.sql)"

# 5. Warmup indicators
curl -X POST http://localhost:8080/api/v1/indicators/warmup/deep \
  -H "Content-Type: application/json" \
  -d '{"symbols":["BTCUSD","ETHUSDT"],"timeframes":["1m","5m"],"limit":250}'

# 6. Wait for signals (2-5 minutes)
sleep 120
curl http://localhost:8080/api/v1/signals/stats | jq

# 7. Run tests
pip install websockets requests
python scripts/testing/websocket-soak-test.py --duration 1 --clients 5
python scripts/testing/run-backtests.py --host localhost:8080 --output ./results
```

**See**: `docs/SIGNALS_STAGING_DEPLOY.md` for detailed guide

## Security

### Implemented

✅ **JWT Authentication**
- Configurable token-based auth
- Secure secret generation
- Token expiry support

✅ **Secret Management**
- Auto-generated secrets via `run.sh`
- `.env` file for environment-specific config
- `.gitignore` prevents secret commits

✅ **Network Security**
- Docker network isolation
- Internal-only services (QuestDB, Redis, Prometheus)
- CORS configuration

✅ **Discord Webhook Security**
- Private channel recommendations
- URL stored in environment (not hardcoded)
- Regeneration guidance if compromised

### Recommended (Production)

⚠️ **HTTPS/TLS**
- Configure SSL certificates (Let's Encrypt)
- Redirect HTTP → HTTPS
- Use `./run.sh ssl-init`

⚠️ **API Rate Limiting**
- Implement per-IP limits
- Per-token limits (if JWT enabled)
- Configure nginx/reverse proxy

⚠️ **Secrets Manager**
- Migrate to AWS Secrets Manager / HashiCorp Vault
- Rotate secrets quarterly
- Audit access logs

## Known Limitations

### Current Constraints

1. **WebSocket Authentication**
   - Not yet implemented (REST API only)
   - Can be added in future release

2. **Backtest Fees/Slippage**
   - Not currently simulated
   - Results optimistic vs. real trading

3. **Signal Deduplication**
   - No cooldown between repeated signals
   - May generate noise in choppy markets

4. **Multi-Instance Scaling**
   - Single instance only
   - Horizontal scaling not tested

### Mitigation

- WebSocket auth: Planned for v2.2
- Backtest accuracy: Document limitations, add parameters
- Signal cooldown: Configurable threshold planned
- Scaling: Test with load balancer before multi-instance
